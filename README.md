# ورقة — محرر PDF عربي

موقع ثابت بواجهة عربية يعمل على جهاز المستخدم، بدون خادم استقبال أو قاعدة بيانات. مكتبات PDF.js وpdf-lib مضمّنة محليًا. لا تحتاج `npm install` ولا توجد مفاتيح API.

## تشغيله محليًا

من مجلد المشروع:

```bash
python -m http.server 8000 --directory dist
```

افتح `http://localhost:8000`. لا تفتح `index.html` بالنقر المزدوج؛ وحدات JavaScript تحتاج خادم HTTP. استخدم متصفحًا حديثًا.

## نشره للناس على GitHub Pages

1. أنشئ مستودعًا **Public** باسم مثل `waraqa-pdf-editor`.
2. فك ZIP وارفع **محتويات** مجلد المشروع إلى المستودع: `dist` و`tests` و`package.json` و`README.md` و`LICENSE` و`.github`؛ لا ترفع ZIP نفسه. احفظ الملفات على فرع `main`. تأكد أن `.github/workflows/pages.yml` موجود في المستودع؛ يمكن إنشاؤه عبر Add file → Create new file إذا لم يظهر عند رفع الملفات.
3. من **Settings → Pages → Build and deployment → Source** اختر **GitHub Actions**.
4. من **Actions → Publish GitHub Pages → Run workflow** شغّل النشر الأول. بعد ذلك كل push إلى `main` ينشر التعديل تلقائيًا.
5. عند نجاح العملية خذ الرابط من صفحة Pages أو بيئة `github-pages`. سيكون عادةً `https://USERNAME.github.io/REPOSITORY/`.
6. فعّل **Settings → General → Features → Issues**. على GitHub Pages يظهر تلقائيًا زر «اقتراح / مشكلة» يوجّه المستخدمين إلى Issues في مستودعك؛ لا يحتاج الموقع خدمة لاستقبال الملاحظات.

تحتاج صلاحيات إدارة المستودع لتفعيل Pages. ملف workflow يستخدم أدوات GitHub Pages الرسمية:
https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

## الاستخدام

- افتح PDF حتى 40 ميغابايت.
- **تعديل نص موجود:** اضغط على عبارة؛ تفتح textarea في مكانها. اكتب فيها أو في المربع الجانبي، ثم زر «تنفيذ / حفظ» أو Enter. Shift+Enter يضيف سطرًا. Esc أو «إلغاء» يتراجع عن التحرير الحالي.
- **حذف:** اختر النص أو العنصر ثم اضغط «حذف النص / العنصر المحدد»، أو زر الحذف العائم. «إلغاء» يغلق صندوق التحرير دون حذف النص.
- **تنسيق وتحريك النص:** خط وحجم ولون وعريض ومائل وتسطير. اسحب المقبض أو استخدم الأسهم. يمكنك تطبيق التنسيق على النصوص القابلة للاستخراج في الصفحة الحالية.
- **صور وعناصر:** اضغط على صورة يكتشفها المحرر، أو اسحب حول منطقة تحتوي صورة/شعار/شكل/جدول. تُفتح المنطقة كعنصر بصري يمكن سحبه، تغيير حجمه من مقبض الزاوية، أو إدخال موقعه وأبعاده بالنقاط في اللوحة الجانبية. يمكن الحفاظ على النسب أو تعطيله. نفّذ أو ألغِ التعديل.
- **صورة أو توقيع جديد:** أضف PNG/JPEG أو توقيعًا مرسومًا، ثم اختر «صور وعناصر» واضغط على الإضافة لتحريكها وتغيير حجمها.
- رتّب الصفحات أو احذفها أو دوّرها. ثم نزّل PDF.

## حدود التنفيذ

هذا **محرر بصري**، وليس محركًا يعيد كتابة بنية PDF أو يعيد تدفق الفقرات. منطقة الأصل تُمسح بخلفية بيضاء، ويُرسم البديل في مكانه الجديد. تحريك رسم أو جدول يحوّل المنطقة المختارة إلى صورة؛ لا يعدّل خلاياه أو مساراته بشكل منفصل. الالتقاط التلقائي للصور يدعم عمليات الصور المعتادة؛ صور الخلفية الكاملة وبعض أنماط PDF تحتاج تحديدًا يدويًا.

الصفحات المعدّلة تُصدّر كصور حتى يظهر النص العربي كما في المتصفح. لا تبقى نصوص تلك الصفحات قابلة للبحث، وقد تفقد الروابط والحقول والتوقيعات الرقمية. الصفحات غير المعدّلة تنسخ مباشرة. الخطوط تعتمد على المتصفح؛ لا نضمن مطابقة الخط الأصلي. الخلفيات غير البيضاء أو العناصر المتداخلة قد تحتاج تعديلًا يدويًا. لا يدعم OCR أو الملفات المشفّرة أو Word. البيانات والتعديلات في الذاكرة وتُفقد عند تحديث الصفحة. التوقيع رسم بصري وليس توقيعًا رقميًا.

## تنظيم الكود

- `dist/index.html`: الواجهة العربية.
- `dist/style.css`: التنسيق وتفاعل hover.
- `dist/app.mjs`: رفع PDF والعرض وتحرير النص وإدارة الصفحات والتصدير.
- `dist/object-editor.mjs`: اكتشاف حدود الصور، التقاط المناطق، التحريك وتغيير الأبعاد والحذف.
- `dist/vendor`: المكتبات وموارد الخطوط وCMaps وWASM، مع تراخيصها.
- `tests`: اختبارات منطق التحرير والعناصر، باستخدام Node.js.
- `.github/workflows/pages.yml`: فحص ونشر تلقائي على GitHub Pages.
- `.github/ISSUE_TEMPLATE`: نموذج ملاحظات المستخدمين.

## فحص الكود

Node.js 22 أو أحدث، بدون تثبيت حزم:

```bash
npm run check
npm test
```

الاختبارات تتحقق من منطق التحديد والاستبدال والمزامنة والتحريك والتنسيق والحذف وحدود الصور. تستخدم واجهة DOM محاكاة؛ لم يُنفّذ اختبار تفاعلي في متصفح حقيقي في بيئة البناء.
